### 1. Security Architecture & Threat Model

AgroBloom AI processes farmer identity records, proprietary agricultural photographs, agronomist credentials, and diagnostic histories. The security posture is structured around defense-in-depth principles:

```
+--------------------------------------------------------------------------+
|                            DEFENSE-IN-DEPTH TIERS                        |
+--------------------------------------------------------------------------+
| 1. Perimeter Tier:  CORS Whitelisting, Rate Limiting, Request Size Caps   |
| 2. Identity Tier:   JWT Signing, Bcrypt Salting, RBAC Role Guards        |
| 3. Application:     Express-Validator, File MIME/Size Verification       |
| 4. Data Layer:      Mongoose Schema Casting, NoSQL Injection Immunity   |
| 5. Edge / PWA:      Isolated IndexedDB Storage, Tokenless Cache Storage  |
+--------------------------------------------------------------------------+
```

### 2. OWASP Top 10 Security Controls & Audit

#### 2.1 A01: Broken Access Control
- **Threat:** Unauthenticated users accessing farmer detection histories or normal farmers performing agronomist prescriptions.
- **Mitigation:**
  - `auth` middleware verifies the cryptographic signature of incoming Bearer JWT tokens on all non-public routes.
  - Role-based authorization verifies `req.user.role === 'agronomist'` or `'admin'` before granting access to prescription and verification endpoints.
  - Detection records are strictly filtered by `user: req.user.id`, preventing horizontal privilege escalation.

#### 2.2 A02: Cryptographic Failures
- **Threat:** Plaintext password exposure or weak token generation.
- **Mitigation:**
  - All user passwords are encrypted using `bcryptjs` with 10 salt rounds before database persistence.
  - User password hashes are explicitly marked with `select: false` in Mongoose schemas, preventing inadvertent inclusion in JSON serialization.
  - JWT tokens are signed using high-entropy secret keys with expiration timestamps.

#### 2.3 A03: Injection (NoSQL & Command Injection)
- **Threat:** Attacker submitting Mongo query operators (e.g., `{"$gt": ""}`) in login forms to bypass authentication.
- **Mitigation:**
  - Mongoose ODM enforces strict schema typing; non-string objects submitted to string fields are cast or rejected prior to query execution.
  - All image file paths generated by Multer use randomly generated UUIDs (`uuidv4()`), completely eliminating path traversal (`../`) and shell injection vectors.

#### 2.4 A04: Insecure Design & File Upload Vulnerabilities
- **Threat:** Uploading malicious executables, PHP scripts, or zip bombs disguised as plant photos.
- **Mitigation:**
  - Multer middleware enforces strict MIME-type validation via `fileFilter`: only `image/jpeg`, `image/png`, and `image/webp` are accepted.
  - File size is strictly capped at $10\text{ MB}$ (`limits: { fileSize: 10 * 1024 * 1024 }`).
  - Uploaded files are renamed with timestamped hashes and stored in an isolated static directory without executable privileges.

#### 2.5 A05: Security Misconfiguration
- **Threat:** Information leakage through stack traces or permissive CORS.
- **Mitigation:**
  - CORS middleware parses an explicit whitelist of origins (`CLIENT_URL`); wildcard (`*`) origins are prohibited when handling credentials.
  - Centralized Express error handler masks raw internal stack traces in production, returning sanitized client error messages.

#### 2.6 A07: Identification and Authentication Failures
- **Threat:** Self-escalation of roles or brute-force credential stuffing.
- **Mitigation:**
  - User registration endpoint explicitly strips and rejects the `admin` role from request payloads; all public accounts default strictly to `farmer`.
  - Expert agronomist status requires administrative verification of uploaded educational certificates.

### 3. PWA & Client-Side Edge Security

1. **Service Worker Cache Guard:** The Service Worker (`client/public/sw.js`) explicitly excludes all `/api/auth/*` requests from caching, ensuring authentication tokens and user credentials are never written to unencrypted browser disk storage.
2. **IndexedDB Isolation:** Offline diagnoses saved in `AgroBloomOfflineDB` store only foliar feature labels, confidence values, and plant names. No sensitive user passwords or server tokens are stored in the IndexedDB schema.
3. **Cross-Site Scripting (XSS) Prevention:** React natively sanitizes interpolated variables against XSS; `dangerouslySetInnerHTML` is strictly avoided across the entire codebase.
